# 项目详情页产品叙事改版设计

## 背景

当前六个项目详情页已经具备使用流程、架构图、证据截图和项目边界，但部分“关键技术决策”仍以 FastAPI、React、Redis、服务边界等通用工程实现为主。招聘者能够看到技术栈，却不能在短时间内判断项目解决了什么问题、提供哪些功能，以及它与普通 Agent Demo 的区别。

本轮改版将详情页的主叙事从“前后端如何连接”转为“用户能完成什么、项目独有机制是什么、为什么有价值”。内容以六个 GitHub 仓库当前代码、README、产品说明和既有真实截图为依据，不增加无法由仓库支持的功能或结果声明。

## 目标

- 让招聘者进入项目页后先理解项目用途和核心功能，再阅读实现。
- 用项目专属能力替代通用框架或分层描述。
- 同时保留足够的技术深度，体现个人开发项目的系统设计能力。
- 中英文页面信息完整对应，保持自然表达。
- 保留现有技术栈、项目状态、角色、GitHub 链接、截图和架构图。

## 非目标

- 不更换架构 SVG、封面或证据截图。
- 不新增运行时依赖、客户端框架、后端接口或数据迁移。
- 不添加未经仓库支持的性能、准确率或生产能力声明。
- 不重新引入“当前验证状态”或验证证据 CTA。

## 统一页面结构

六个项目的中英文详情页统一使用以下顺序：

1. **项目解决什么 / What it solves**：说明目标用户、实际问题和最终产出，不以技术栈开头。
2. **核心功能 / Core capabilities**：列出 4–6 项用户可以实际完成的操作。
3. **使用流程 / How it works**：保留四步流程，并补充关键输入与输出。
4. **项目亮点 / Project highlights**：三个项目专属亮点，每项遵循“用户能力 → 独有机制 → 价值”的表达。
5. **系统架构 / System architecture**：保留现有架构图，在此集中解释技术组件如何支撑功能。
6. **项目边界 / Project scope**：以 2–3 句说明适用范围和明确不覆盖的场景。

“核心功能”使用两列能力列表，390px 移动端回落为单列。截图放在相关功能或亮点附近；架构图位于项目亮点之后。现有 hero 元数据、技术栈、状态、角色和唯一 GitHub CTA 不变。

## 写作规则

- 亮点标题描述产品能力或领域机制，不以框架名称、协议或前后端分层作为标题。
- 技术名词只有在解释独有机制时出现；FastAPI、React、SSE、Redis 等通用组件主要留在技术栈和系统架构中。
- 每个亮点必须回答：用户获得什么能力、系统如何做到、这对该项目为何重要。
- 不用“全栈”“高性能”“智能”等空泛词替代具体功能。
- 项目边界不记录本轮复现过程、API 缺失或环境搭建过程；只保留会影响使用者理解的产品范围。
- 边界文案不能把实验性项目包装成生产系统，也不能用长篇防御性说明压过成果。

## 六个项目的内容重点

### My Company Brain

**项目解决什么**：为企业团队提供可治理、可追溯并带权限边界的多知识库工作台，使业务成员能够管理资料、创建场景、跨知识源问答并查看来源。

**核心功能**：知识源管理；文档、表格与知识页面导入；业务场景和处理任务；全域问答与连续追问；片段、页面、表格和图片来源；成员与管理端知识治理。

**项目亮点**：

1. 三条知识路径分别处理页面事实、文档语义和实体关系，避免用单一 RAG 勉强覆盖所有资料形态。
2. 全域问答可以组合不同知识路径，同时保留页面、表格、图片和片段级来源。
3. 权限过滤进入实际检索边界，公开、本人私有和团队授权知识不只依赖前端隐藏。

**项目边界**：自托管企业知识工作台；不宣称生产级高可用、企业 SSO 或大规模负载能力。

### GraphRAGAgent

**项目解决什么**：把文档转换为既能可视化探索、又能用于问答的知识图谱，使用户可以沿实体关系理解资料并继续追问。

**核心功能**：文档上传与索引进度；实体关系图浏览；实体、路径和局部子图搜索；节点详情与邻居探索；多轮问答会话；引用节点回到图谱。

**项目亮点**：

1. 从文档自动完成页面组装、实体抽取、全局图谱合并与向量索引。
2. 问答 Agent 同时使用实体、邻居、路径和原文语义检索，不把 GraphRAG 简化为“向量搜索旁边放一张图”。
3. 图谱探索和问答共享同一批知识对象，用户可以从节点发问，也可以从回答引用回到实体关系。

**项目边界**：用于本地资料的知识探索，不包装成多人企业知识治理平台。

### 合同审核多智能体工作流

**项目解决什么**：让 AI 承担合同字段抽取和风险初筛，同时把关键判断保留给人工审核者，并将整个过程组织成可恢复的审核会话。

**核心功能**：合同上传与解析；关键字段抽取与核验；风险条款扫描；高中低风险分级路由；人工决策与审核会话恢复；报告导出。

**项目亮点**：

1. 高风险逐条审批、中风险批量确认、低风险自动通过，使风险等级真正改变处理流程。
2. 风险扫描前先提取合同双方、金额、日期和管辖法律，让人工先核验关键事实。
3. 人工决策支持备注门槛、幂等写入、撤销和流程恢复，使 HITL 成为真正的工作流节点。

**项目边界**：用于合同初筛和审核协作，不提供法律意见或风险识别准确率承诺。

### AI 数学动画生成工作台

**项目解决什么**：把教师的自然语言教学需求转换为可审阅的教学计划、版本化 Manim 代码和可交付视频，而不是直接执行一次性模型代码。

**核心功能**：教学 Prompt；ContentPlan 生成与编辑；Manim CodeVersion；Preview/Final 渲染；视频、缩略图和日志；质量诊断与产物下载。

**项目亮点**：

1. 先把需求整理为受众、时长、场景、公式步骤和假设明确的 ContentPlan，再生成动画代码。
2. Prompt、计划、代码和渲染产物形成不可变版本链，可以定位每次修改对应的结果。
3. 生成代码经过白名单、编译和 Scene 检查后才进入隔离容器，并对视频时长、帧率和严重视觉异常执行确定性检查。

**项目边界**：需要教师审阅的创作工作台；不保证任意数学主题都能一次生成最终视频。

### NL2SQL 数据分析工作台

**项目解决什么**：让使用者用自然语言查询已知业务数据库，并在一次对话中获得 SQL、结果表格、图表和分析说明。

**核心功能**：自然语言查询；DDL、业务文档和 SQL 示例管理；多轮对话；SQL 生成、查看与执行；结果表格；自动图表和分析说明。

**项目亮点**：

1. 同时检索 DDL、业务文档和历史 SQL 示例，让模型理解表结构、业务命名和查询范式。
2. 将检索、SQL 生成、校验、执行和解释呈现为可观察步骤，使用户能够理解结果如何产生。
3. 一次查询同时返回 SQL、数据表、图表配置和文字分析，形成完整的数据分析交付。

**项目边界**：用于已知数据库和训练语境下的辅助分析，不替代数据库权限、查询沙箱或人工核验。

### ITA-Maskit

**项目解决什么**：帮助审计人员在本地批量处理多种格式的敏感资料，通过可维护规则完成遮盖或伪名化并留下审计记录。

**核心功能**：CLI 与 Windows GUI；多文件、多格式本地处理；规则预验证；遮盖和确定性伪名化；人员清单匹配；统计和审计日志。

**项目亮点**：

1. 表格按列处理，邮件、PDF 和 Word 全文扫描，同一工具覆盖结构化和非结构化审计资料。
2. YAML 将字段匹配、遮盖模板和规则版本变成可维护数据，规则变化不要求修改核心代码。
3. HMAC 与用户提供的 pepper 让同一敏感值跨文件保持一致伪名，隐藏原值的同时保留跨表关联分析能力。

**项目边界**：确定性伪名化不是加密；OCR 图片和原样 PDF 遮盖继续明确标为 beta。

## 中英文策略

- 两种语言使用相同的章节顺序、功能数量、亮点主题和边界范围。
- 中文优先使用明确的动作和业务对象；英文使用自然的产品与工程表达，不逐字翻译中文句式。
- 专有名词、功能名和仓库实际对象保持一致，例如 ContentPlan、CodeVersion、Preview/Final、HITL、GraphRAG。

## 实现范围

- 修改十二份 `src/content/projects/{zh,en}/*.md`。
- 如现有 prose 样式不足，增加一个只服务于“核心功能”列表的响应式规则；不创建新运行时组件。
- 更新项目内容单元测试和 Playwright 测试，以覆盖新章节、顺序、项目专属亮点、图片和 CTA 保留行为。
- 不修改 schema、路由、架构图、封面或证据图资产，除非实施时发现新结构需要纯展示层的无障碍修正。

## 验收标准

- 六个项目的中英文页面均按六段新结构渲染，标题顺序一致。
- 每页包含明确的项目用途、4–6 项核心功能和三个项目专属亮点。
- 不再出现“用 FastAPI 固定前后端边界 / Use FastAPI as the frontend boundary”等通用亮点标题。
- 每个亮点能对应仓库中的真实功能或机制，不新增无来源的结果声明。
- 现有项目状态、角色、技术栈、架构图、截图和唯一 GitHub CTA 保持存在。
- 390px 下核心功能列表为单列，页面无横向溢出；架构图继续只在自身容器内横向滚动。
- 单元测试、构建、链接检查、桌面与移动端 E2E 以及完整 `npm run validate` 通过。
- 发布后十二条中英文生产项目路由均通过结构、图片、CTA 和无障碍抽查。
